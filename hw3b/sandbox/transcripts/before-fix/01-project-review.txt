# Final project: semantic search across Church and BYU texts

Search the scriptures, October 2026 general conference, and selected BYU Speeches with one embedding model. Results show the matching passage, a cosine similarity score, and a link to the original source. This is retrieval only; it does not generate an answer or claim that the highest score is doctrinally correct.

## Data included in this first version

- **Scriptures:** 41,995 verses from all five standard works. The project reuses the `hw2d/cache-verse` embeddings and text already created for class, so these verses do not need to be embedded again.
- **General conference:** the 38 local text files in `hw2e/talks`, corresponding to October 2026. The builder checks their order and titles against the [official conference index](https://www.churchofjesuschrist.org/study/general-conference/2026/10?lang=eng) so each result gets the right source URL. More conference folders can be added in `conferences.json`.
- **BYU Speeches:** four published transcripts listed in `speeches.txt`. Add more BYU Speeches URLs to that file and rebuild. Speeches without published text are skipped; [BYU explains why some transcripts are unavailable](https://speeches.byu.edu/faq/).

Talks and speeches are split into overlapping passages of about 180 words. All three sources use OpenAI `text-embedding-3-small`, and search compares normalized vectors with cosine similarity. The generated indexes stay in `data/`, which Git ignores. Do not commit the downloaded text or generated index if you plan to share this repository publicly without checking the source publishers' permissions.

## Run it

From `CS 301R/final project` in PowerShell:

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
..\.venv\Scripts\python.exe build_index.py
..\.venv\Scripts\python.exe search.py "God knew me before I was born"
..\.venv\Scripts\python.exe search.py "God knew me before I was born" --per-source --limit 2
..\.venv\Scripts\python.exe search.py "grace helps us change" --source byu
..\.venv\Scripts\python.exe search.py "temple covenants" --source conference --limit 10
..\.venv\Scripts\python.exe search.py --stats
```

The OpenAI key is read from the course root `.env` as `OPENAI_API_KEY`. Building the conference and BYU indexes makes embedding API calls; each search embeds only the query. The existing scripture index was built with the same model. By default, results rank together across sources. Use `--per-source` to see the strongest matches from each collection, or `--json` for structured results for an app or evaluation script.

To add speeches, put one `https://speeches.byu.edu/talks/.../` URL per line in `speeches.txt` and run `build_index.py --source byu`. To add a conference, use the existing `classwork/2e/download_gc_talks.py` downloader to save its talks to a folder, add that folder and its official conference index URL to `conferences.json`, then run `build_index.py --source conference`. Folder paths in `conferences.json` are relative to that file. Matching conference folders and URLs are required so citations remain correct.

The initial BYU list is deliberately small enough to verify by hand. Expanding to the full BYU archive or many decades of conference talks would need a source inventory, incremental indexing, and retrieval evaluation. Embeddings can miss passages that express an idea indirectly, as the `hw2d` experiments showed, so inspect the linked source before relying on a result.

"""Build local embedding indexes for conference talks and BYU Speeches."""

import argparse
import json
import unicodedata
from pathlib import Path
from urllib.parse import urljoin, urlparse

import numpy as np
import requests
from bs4 import BeautifulSoup
from openai import OpenAI

from settings import DATA_DIR, MODEL, PROJECT_DIR


CONFERENCES = PROJECT_DIR / "conferences.json"
SPEECH_URLS = PROJECT_DIR / "speeches.txt"
USER_AGENT = "CS301R-semantic-search/1.0 (personal course project)"
WINDOW_WORDS = 180
OVERLAP_WORDS = 30
BATCH_SIZE = 100


def normalized_title(title: str) -> str:
    folded = unicodedata.normalize("NFKD", title).casefold()
    return "".join(character for character in folded if character.isalnum())


def chunks(text: str) -> list[str]:
    words = text.split()
    if not words:
        return []
    result = []
    step = WINDOW_WORDS - OVERLAP_WORDS
    for start in range(0, len(words), step):
        piece = words[start : start + WINDOW_WORDS]
        if len(piece) < OVERLAP_WORDS and result:
            break
        result.append(" ".join(piece))
        if start + WINDOW_WORDS >= len(words):
            break
    return result


def fetch_page(url: str) -> BeautifulSoup:
    response = requests.get(url, headers={"User-Agent": USER_AGENT}, timeout=30)
    response.raise_for_status()
    return BeautifulSoup(response.content, "html.parser")


def conference_links(conference_url: str) -> list[tuple[str, str]]:
    parsed = urlparse(conference_url)
    if parsed.netloc != "www.churchofjesuschrist.org" or not parsed.path.startswith("/study/general-conference/"):
        raise ValueError("Conference URL must be a Church general conference page")
    prefix = parsed.path.rstrip("/") + "/"
    links = []
    for anchor in fetch_page(conference_url).select("li a[href]"):
        title = anchor.select_one("p.title")
        href = anchor.get("href", "")
        path = urlparse(href).path
        if title and path.startswith(prefix) and "session" not in path:
            links.append((title.get_text(" ", strip=True), urljoin(conference_url, href)))
    if not links:
        raise ValueError("No talk links found on the conference page")
    return links


def conference_records(folder: Path, conference_url: str) -> tuple[list[dict], int]:
    files = sorted(folder.glob("*.txt"))
    links = conference_links(conference_url)
    if not files or len(files) != len(links):
        raise ValueError(f"Found {len(files)} local talks but {len(links)} source links; check the conference folder and URL")

    records = []
    for path, (source_title, url) in zip(files, links):
        lines = path.read_text(encoding="utf-8").splitlines()
        if len(lines) < 3:
            raise ValueError(f"Talk has no body: {path}")
        speaker, title = lines[:2]
        if normalized_title(title) != normalized_title(source_title):
            raise ValueError(f"Talk order or title mismatch: {path.name} / {source_title}")
        for index, text in enumerate(chunks("\n".join(lines[2:]))):
            records.append({
                "source": "conference",
                "document_id": url,
                "title": title,
                "speaker": speaker,
                "url": url,
                "chunk": index + 1,
                "text": text,
            })
    return records, len(files)


def all_conference_records(config_path: Path) -> tuple[list[dict], int]:

# Source review

This repository is a small command-line semantic retrieval system. It builds local indexes for conference talks and BYU speeches, reuses a pre-existing scripture index, embeds a query with OpenAI, and ranks normalized vectors by dot product (cosine similarity). It does not generate answers.

## Files

### `README.md`

Describes the scope, data sources, setup and CLI examples. It also documents important operational assumptions that are not contained in this directory: the scripture cache is expected at `../hw2d/cache-verse.{npy,json}`, conference text is expected at `../hw2e/talks`, an API key is expected in the parent directory's `.env`, and generated indexes go in `data/`. It notes copyright, retrieval limitations, and how to extend the two source lists.

### `settings.py`

Defines paths relative to the source file (`PROJECT_DIR`, parent `COURSE_DIR`, and `DATA_DIR`), fixes the embedding model to `text-embedding-3-small`, and loads environment variables from `../.env`.

### `build_index.py`

Builds the conference and BYU indexes (not the scripture index).

* Reads conference configurations, fetches each official conference index, extracts talk titles/URLs, and pairs those links positionally with sorted local `.txt` files. Each local file is interpreted as speaker on line 1, title on line 2, and body thereafter. Normalized titles are checked to detect ordering mismatches, and duplicate talk URLs across configured conferences are rejected.
* Reads, validates, canonicalizes, and deduplicates BYU URLs. It downloads each page, extracts transcript headings and paragraphs from `.individual-speech__content`, and extracts title, speaker, and optional date. Missing or very short transcripts are skipped.
* Turns documents into chunk records, embeds batches of 100 after prefixing every chunk with its title and speaker, converts vectors to `float32`, and L2-normalizes each row.
* Atomically replaces `data/conference.{npy,json}` and `data/byu.{npy,json}` using temporary files. JSON stores the model and record metadata; NPY stores vectors.

The source relies on the current HTML structure of both sites and always downloads and re-embeds a selected collection from scratch.

### `search.py`

Loads selected NPY/JSON indexes, memory-mapping vector arrays. Non-scripture indexes are checked for the configured model and for matching vector/record counts. Scripture records receive Church URLs from volume/book mappings and a fallback slug rule.

A query is embedded and normalized, then scored against each index with a matrix-vector product. The code takes a candidate pool of at least 50 (or `limit * 30`) per source, globally sorts it, and returns at most one passage per document. Thus a talk or speech cannot occupy several result positions, while each scripture verse is effectively its own document. `--per-source` returns the requested number for each collection; other options provide source filtering, JSON, counts, and human-readable excerpts.

### `conferences.json`

Configuration for conference ingestion. The one entry connects the official October 2026 conference index URL to the external local folder `../hw2e/talks`. Folder paths are resolved relative to this JSON file.

### `speeches.txt`

Seed inventory of four BYU Speech transcript URLs. Blank lines and comments are allowed. The builder accepts only HTTPS URLs on `speeches.byu.edu` under `/talks/`.

### `requirements.txt`

Declares Beautiful Soup, NumPy, the OpenAI client, python-dotenv, and Requests with minimum versions. There is no lock file or upper bounds.

## Passage chunking

Scriptures follow a different path from the other collections: this project does not parse or chunk them. It assumes the reused cache contains 41,995 records and treats every cached verse (`record["text"]`) as one searchable passage.

Conference and BYU documents use the same whitespace-based `chunks()` function:

* Split all text with Python `str.split()`, so paragraph breaks and headings are discarded as boundaries and whitespace is normalized.
* Take windows of at most **180 words**.
* Advance by **150 words**, producing a **30-word overlap** between full adjacent windows.
* Keep the final partial window. The code has a guard against adding a trailing piece shorter than 30 words when a prior piece exists; with the current step/window arithmetic and immediate end check, normal iterations make final windows at least 31 words, so this guard is effectively redundant.
* Number chunks from 1 within each document.

For conference text, only the body after the first two lines is chunked. For BYU text, selected `h2`, `h3`, and `p` elements are joined and then chunked. The embedding input is `title + newline + speaker + newline + chunk`, although the displayed/stored passage text is only the chunk. Search returns only the highest-scoring chunk from any given talk or speech.

## Three most useful improvements

1. **Add a retrieval evaluation suite, then improve ranking against it.** Create a small, versioned set of queries with relevant passages/source types and report recall@k, MRR, and per-source results. This is especially important because verse-sized scripture embeddings are being compared directly with title/speaker-prefixed 180-word embeddings; score distributions may not be comparable. Evaluation can guide source calibration and a hybrid lexical/semantic ranker (useful for exact names and quotations), rather than relying on plausible demo queries.

2. **Use structure-aware passages and expose context.** Split talks at paragraph/sentence boundaries near a token budget instead of cutting every 150 whitespace-separated words. Store character/paragraph locations, link to anchors where available, and optionally return the neighboring chunk. This avoids broken ideas, preserves headings as useful section context, and makes results easier to verify. Consider verse groups with overlap for scripture too: one verse often lacks enough context, while the present three collections have substantially different passage granularity.

3. **Make indexing incremental, reproducible, and resilient.** Cache fetched source text and embeddings by canonical URL plus a content hash, update only changed documents, checkpoint batches, and retry rate limits/transient HTTP or API failures with backoff. Record model, dimensions, build time, chunking parameters, and source hash in every index (including imported scripture), and validate finite/nonzero normalized vectors at load time. A lock file and fixture-based parser tests would also protect against dependency and website-markup changes. This would reduce API cost and make expansion beyond the current four speeches/one conference practical.
